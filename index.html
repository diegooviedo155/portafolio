Flagship Case Study · SaaS

Tandi

From scattered WhatsApp orders to a structured digital sales workflow.

A SaaS platform designed to simplify online selling for entrepreneurs, resellers, and small businesses.

Visit Tandi Contact me
The Problem

Selling through chat creates operational chaos

Entrepreneurs, resellers, and small shops commonly manage sales across WhatsApp chats, Instagram posts, manual catalogs, price lists, and spreadsheets. The core problem is not merely listing products online—it is organizing the entire commercial operation (variants, deposits, pre-orders, stock, and delivery tracking) without technical overhead.

The Solution

One structured workflow from catalog to dispatch

Tandi centralizes the selling experience into a single platform where each store manages its online catalog, orders, deposits, balances, inventory, pre-orders, and shipping—supporting businesses that sell from own stock, on demand (por encargo), or in hybrid mode.

Product Walkthrough (tandi.com.ar)

Product Architecture & Verified Capabilities

Storefront & Custom Link

Dedicated store URL ready to share on WhatsApp statuses, Instagram bios, and broadcast groups.

Catalog & Variant Stock

Interactive galleries by size and color with independent stock tracking per variant.

Stock, Pre-Order & Hybrid Modes

Supports immediate-delivery stock, on-demand pre-orders (por encargo), or both combined.

Orders, Deposits & Balances

Centralized order intake with deposit (seña) management, pending balance control, and customer history.

Wholesale Purchasing Workflow

Built-in wholesale purchasing notebook (cuaderno de compra mayorista) to consolidate supplier restocks.

Payments, Shipping & Promos

Mercado Pago & bank transfers, postal-code shipping quotes, QR/barcode labels, coupons, packs, and combos.

Technical Challenges & Architecture Focus
  • Variant & Inventory Modeling: Representing size/color matrices with independent stock counts alongside on-demand items in a single storefront.
  • Hybrid Order Lifecycle: Coordinating state transitions across partial deposits (señas), remaining balances, wholesale sourcing, and dispatch.
  • External Integrations: Connecting Mercado Pago payment confirmation, postal-code shipping quotes, and QR/barcode label generation.
  • Mobile-First Seller UX: Enabling store owners to upload products, manage orders, and generate labels directly from a phone.
Decisions & Product Learnings
  • Workflow-First Product Design: Structured around real WhatsApp/Instagram reseller workflows rather than generic e-commerce templates.
  • No-Friction Buyer Tracking: Automatic per-order tracking links reduce repetitive status inquiries without forcing buyer account creation.
  • Key Learning: For small merchants, reducing operational steps (deposits, wholesale lists, dispatch labels) matters more than adding complex storefront customization.

How I approach technical decisions

Architecture · Migration

Incremental React-to-Angular migration via Microfrontends

Context
Production enterprise web applications at Eldar evolving over multi-year release cycles.
Problem
A full rewrite would freeze product delivery and introduce high regression risk.
Approach
Co-hosted React and Angular microfrontends behind shared routing and composition boundaries.
Technical Decision
Migrated domain slices incrementally while keeping production systems continuously live.
Takeaway
Incremental boundaries let teams ship product features while retiring legacy modules safely.

Design Systems · Web Components

Cross-framework UI library with Stencil.js & Nexus

Context
Multiple teams building Angular and React microfrontends needing visual and behavioral consistency.
Problem
Duplicating components per framework caused visual drift and double maintenance.
Approach
Encapsulated UI primitives as framework-agnostic Web Components compiled with Stencil.js.
Technical Decision
Standardized on Web Components published and versioned through Nexus instead of parallel UI kits.
Takeaway
Strict versioning and standard browser primitives scale better than framework-coupled libraries.

↓

↓
Consumers Angular & React Microfrontends
Monorepo · Type Safety

Shared Zod contracts across NestJS, Next.js, and React Native

Context
Building Fynta across web, mobile, and backend API simultaneously.
Problem
API payload drift between backend and clients slows down iteration and introduces runtime bugs.
Approach
Structured an Nx monorepo with shared TypeScript types, Zod schemas, and a typed HTTP client.
Technical Decision
Enforced single-source validation schemas at the boundary instead of duplicating DTOs.
Takeaway
Shared contracts catch breaking changes at compile time before they reach production.
